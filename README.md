# 竞彩当日分析

给自己看的当天竞彩工作台。Go 后端把场次和结果写入 SQLite，页面只读库。

**不会每次打开页面都请求 AI。** grok-4.6 只在两种时候调用，而且每种快照只写一次：

1. 当天第一次抓到这场（首抓 `open`）
2. 开球前 30 分钟再抓一次（临场 `close`）

库里已经有对应快照，再点「立即抓取」也只会补新场，旧场跳过。

## 跑起来

```bash
cp .env.example .env
# 填 APINEBULA_API_KEY；不填也能抓竞彩、算概率、写库，白话用本地模板

make dev
```

浏览器打开 http://localhost:5173

- 后端 `http://127.0.0.1:8090`
- 前端开发 `http://localhost:5173`（/api 代理到 8090）
- 数据库 `data/jingcai.db`

## 页面上有什么

胜、平、负；大 2.5 / 小 2.5；比分概率表；一段人话。没有凯利、价值差、分析步骤。

## 调度

- 每天 10:00（上海时间）全量首抓
- 每 20 分钟补当天新挂的场
- 每场开球前 30 分钟临场抓一次
- 进程重启后从 SQLite 恢复未开场任务，已有快照不重跑模型

## AI 调用日志

每次外部分析请求都会异步写入 `logs/ai/ai-YYYY-MM-DD.jsonl`。日志包含请求 ID、研判来源、模型、接口地址、耗时、HTTP 状态、完整请求/返回内容和失败阶段，不记录 API Key 或请求头。

```bash
make ai-logs
```

默认保留 48 小时，服务启动时及运行期间每小时自动删除过期日志。可通过 `AI_LOG_DIR` 和 `AI_LOG_RETENTION` 调整。

详情页会显示价值差和凯利松紧（数字 + 松/中/紧），不展示怎么算出来的。凯利参考：>1.02 松，0.96–1.02 中，<0.96 紧。
